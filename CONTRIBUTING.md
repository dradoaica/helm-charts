# Contributing to helm-charts

Thanks for your interest in contributing! This repository is a curated collection of community Helm charts for
underrated open-source projects. Bug fixes, version bumps, new values, and well-justified new charts are all welcome.

## Getting Started

If this is your first contribution, look for issues labelled `good first issue` or `help wanted`.

Small fixes such as typos, broken links, or wrong defaults in a README can go straight to a pull request without an
issue.

For anything larger, such as a new chart, a breaking values change, or a new feature, open an issue first so the
approach can be agreed before you invest time.

Security vulnerabilities must **not** be reported in public issues. See [SECURITY.md](./SECURITY.md).

## Repository Layout

```
charts/<chart-name>/
  Chart.yaml              # chart metadata: version, appVersion, maintainers, sources
  values.yaml             # defaults, each value documented with a `# --` helm-docs comment
  templates/              # manifests, _helpers.tpl, NOTES.txt, tests/
  examples/minimal-values.yaml
  README.md               # generated by helm-docs, do not edit by hand
DEV_NOTES.md              # local MicroK8s setup and install commands
```

## Development Setup

You need [Helm](https://helm.sh/docs/intro/install/) 3, [helm-docs](https://github.com/norwoodj/helm-docs), and a test
cluster. [DEV_NOTES.md](./DEV_NOTES.md) walks through setting up MicroK8s on Ubuntu or Windows (via Multipass) and
installing each chart.

## Making Changes

### 1. Bump the chart version

Every change to a chart's contents needs a new `version` in its `Chart.yaml`. Releases are cut automatically on push to
`main` by [chart-releaser](https://github.com/helm/chart-releaser-action), which only publishes charts whose version
does not already exist as a release. A change without a version bump is never released.

Versioning follows the upstream application:

- `version` major.minor tracks `appVersion` major.minor (for example `ignite` 2.18.x deploys Ignite 2.18).
- Bump the **patch** for chart-only fixes and additions.
- When upgrading the application, set `appVersion` and move `version` to the matching major.minor line.
- Call out breaking values changes, such as renamed or removed keys or changed defaults, in the PR description.

### 2. Document values

Each key in `values.yaml` needs a helm-docs comment:

```yaml
# -- Name of the existing Secret containing the ignite user password
name: ""
```

Then regenerate the chart README:

```
helm-docs --chart-search-root charts
```

Commit the regenerated `README.md` together with the change. If the change affects the chart list or its stable/preview
lines, update the root [README.md](./README.md) as well.

### 3. Lint and render

```
helm lint charts/<chart-name>
helm template test charts/<chart-name>
helm template test charts/<chart-name> -f charts/<chart-name>/examples/minimal-values.yaml
```

Also render with the feature you touched switched on (for example `--set ssl.enabled=true`) and check the output.

### 4. Install and test

Install the chart on a real cluster and run its tests:

```
helm install <chart-name> ./charts/<chart-name> -n <namespace>
helm test <chart-name> -n <namespace>
```

For clustered charts (`ignite`, `ignite-3`, `aspnetcore-ignite-server`), test with more than one replica and check that
`helm upgrade` from the previous chart version works.

## Chart Conventions

New and changed templates should stay consistent with the existing charts:

- **Secrets**: every credential supports `existingSecret` (with overridable key names) alongside a chart-managed Secret
  controlled by `manageSecret`. Never render a secret value into a ConfigMap or a plain environment variable. The one
  known exception is documented in [SECURITY.md](./SECURITY.md#known-limitations).
- **Extensibility**: keep the common hooks the charts share: `extraEnvVars`, `extraEnvVarsCM`, `extraEnvVarsSecret`,
  `extraVolumes`/`extraVolumeMounts`, `podAnnotations`, `nodeSelector`, `tolerations`, `affinity`,
  `topologySpreadConstraints`, `resources`, and `global.imagePullSecrets`.
- **Secure defaults**: non-root `securityContext`, `ClusterIP` services, and no privileged containers unless the
  application genuinely needs them. `clamav-openshift` must stay compatible with OpenShift's restricted SCC (arbitrary
  UID, no root).
- **Naming**: use the helpers in `_helpers.tpl` for names and labels, and don't hard-code release names.
- **Defaults should work**: `helm install` with no values must produce a running deployment.

## Proposing a New Chart

New charts should target a mature, actively maintained open-source project that lacks a good community chart. In the
issue, explain why existing charts don't fit. A new chart must include `Chart.yaml` with `maintainers`, `sources`, and
`home`, a documented `values.yaml`, `examples/minimal-values.yaml`, a `tests/test-connection.yaml`, a generated README,
and install/uninstall entries in `DEV_NOTES.md`.

## Pull Requests

- Keep each PR focused, ideally on one chart. Changes to several charts are fine when they apply the same cross-cutting
  change, such as adding `existingSecret` support everywhere.
- Commit messages start with the affected chart name (s), for example `ignite-3: add existingSecret support for SSL`.
- Fill in the [pull request template](./.github/PULL_REQUEST_TEMPLATE.md) checklist, and mention which cluster and
  Kubernetes version you tested on.
